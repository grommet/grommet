## FormField
Documentation for this component: https://v2.grommet.io/formfield

### Theme backgrounds

- `formField.background` accepts a `BackgroundType` and supplies the normal
  input surface. It paints only the content area, not the label, help, error,
  or info messages. It is undefined by default, so existing themes do not change.
- `formField.<inputName>.background` overrides the shared surface for a direct
  input child, or an input generated by `component` inside a `Form`. Input names
  are camelCase, such as `textInput`, `checkBoxGroup`, and `radioButtonGroup`.
  Generated fields without `component` use `textInput`. Wrappers are not searched
  recursively for inputs.
- Each `formField.<inputName>` also accepts `BoxPartThemeType` properties, and
  its `hover` and `error` accept `BoxStateThemeType`. These style the FormField content
  wrapper; for groups, they apply to the group as a whole, not individual
  options. Use `checkBox.container.*` or `radioButton.container.*` to style an
  individual option label. `formField.checkBox.pad` retains its legacy behavior
  of forwarding padding to a direct CheckBox child. An explicit per-input
  `border` overrides the default inner FormField border; set it to `false` to
  remove that border for a particular input type.
- `formField.<inputName>.error` applies only while that input's FormField is in
  error. It can override `background`, `border`, `elevation`, `pad`, and `round`
  on the content wrapper. Normal border size and side are retained for partial
  error border objects; shared `formField.error` border/background values remain
  fallbacks. An explicit error border can restore a normally disabled border.
  Omitted error parts preserve existing styling. Disabled and read-only fields
  retain their existing state styling rather than applying the per-input error
  part. Hover remains suppressed while invalid, and `contentProps` and existing
  extension hooks retain their precedence.
- `formField.hover.background` and
  `formField.<inputName>.hover.background` control the content surface on hover.
  Hover styling is suppressed while disabled, read-only, invalid, or focused.
  Hover border styling continues to follow the border position.
- An undefined per-input background inherits the shared background. Set both
  the normal and hover per-input backgrounds to `'transparent'` to opt a group
  out of both shared surfaces. Individual controls and their labels can still
  be themed separately: use `checkBox.control.*` or `radioButton.control.*` for
  the control and `checkBox.container.*` or `radioButton.container.*` for its
  label. Each control supports distinct unselected and selected hover fills.

Existing state background placement and priority are unchanged: an inner border
uses the read-only, error, then disabled background on the content; an outer
border uses the error, focus, then disabled background on the outer field.
An outer state fill is not covered by the new normal surface. When the selected
state has no background, the normal surface remains. Borderless fields use the
normal and hover surfaces on their content. Instance `contentProps` are applied
last and can override the content background, including state backgrounds.

See the Custom Themed Background story for a contrasting form surface and
transparent checkbox and radio groups. Custom themes should check contrast
between their input surfaces, text, control marks, borders, and focus indicators.
